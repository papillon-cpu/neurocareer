# Памятка для продолжения работы

Репозиторий: приватный, ветка `feat/foundation-landing`. Проверки: `npm run typecheck && npm run lint && npm test && npm run build`; сквозные: `npm run test:e2e` (нужен Google Chrome; сам собирает сайт и готовит базу `.data/e2e`) (тесты идут по одному файлу: в каждом своя встроенная БД).

## Готово
1. План, архитектура, дизайн-система, лендинг
3. Регистрация и вход, роли, кабинеты
4. Резюме: редактор, версии, импорт PDF/DOCX с проверкой, печать в PDF
5. Три авторских теста, отчёты
6. AI-шлюз (Claude и GPT), консультант, AI в резюме, AI-пояснение к отчёту (нужны ключи, на живых моделях не проверялись)
8. Оплата: 500 ₽ доступ сотрудника, подписка работодателя, контакты (тестовый провайдер)
7. Вакансии и подбор: вакансии с модерацией, разбор требований (AI или правила), объяснимый подбор по опубликованным профилям, история и жалобы, открытие контактов с показом цены
9. Приватность: публикация, контакты, отзыв, удаление, журнал
10. Сквозные тесты Playwright, инструкция по деплою (`docs/DEPLOY.md`), чек-лист (`docs/LAUNCH_CHECKLIST.md`), `/api/health`, блокировка пользователей в админке, главная с выбором роли, демо-переключатель

## Осталось
- **Подключение реального платёжного провайдера** по интерфейсу `BillingProvider` (нужен выбор провайдера и аккаунт заказчика).
- **AI на живых моделях**: из России нужен ключ GigaChat (`GIGACHAT_AUTH_KEY`, `GIGACHAT_MODEL` в `.env.local`; провайдер добавлен, проверен тестами с подменой сети, вживую не запускался; адреса и сертификат Сбера сверить с актуальной документацией). Anthropic и OpenAI в России официально недоступны, затем прогнать консультанта, резюме, отчёт, разбор вакансии и вывод по кандидату.
- Готово без ключей (проверено тестами, но AI-части и почта не проверены вживую): общее хранилище ограничения частоты в БД, сброс пароля по ссылке из письма, избранные кандидаты и история открытых контактов, расширенный словарь синонимов и пул подбора до 2000, AI-разбор свободных ответов по рубрике (`open_feedback`).
- **Почта**: без `RESEND_API_KEY` и `MAIL_FROM` письма в разработке печатаются в консоль сервера, в production не отправляются (сброс пароля не будет работать). Нужен аккаунт почтового сервиса и домен отправителя; также задайте `APP_URL`.
- Юридическая проверка текстов согласий (`src/modules/consent/texts.ts`, версия `2026-10-draft-1`), сроков хранения и политики удаления.

## Заметки по этапу 7
- Демо-данные для ручной проверки: `npm run db:seed -- --demo`, затем `npx tsx scripts/seed-demo-matching.ts` (останавливайте dev-сервер: БД `.data/` открывается одним процессом). Админ для локальной проверки: `ADMIN_EMAIL`/`ADMIN_PASSWORD` при `db:seed`.
- Не проверено на живых моделях: `vacancy_analysis` и `match_explain` (нет ключей); нужны согласие кандидата `ai_matching` и тексты согласия на проверку юристом (добавлен текст `ai_matching`, версия `2026-10-draft-1`).
- Известные ограничения: см. конец раздела «Вакансии и подбор» в docs/ARCHITECTURE.md.
